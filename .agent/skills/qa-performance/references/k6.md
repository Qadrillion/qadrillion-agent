# Existing k6 workload adaptation

Use only if the team already selects k6 for this risk. Inspect `k6 version`,
`k6 run --help`, the existing script and its actual metrics before changing it.
The repository's stdlib reference helper does not require k6.

1. Name the operation mix and iteration boundary. A k6 iteration can contain
   several requests: an arrival rate in iterations/second is not automatically
   requests/second. Keep think time and data cardinality explicit.
2. Choose an executor for the question. Closed workloads couple offered work to
   response time; arrival-rate workloads schedule iterations independently and
   require enough generator capacity. Record dropped iterations and achieved
   work instead of claiming the requested rate was sustained.
3. Use `check` for the expected business response and thresholds for a failing
   process verdict. Checks alone do not fail k6's exit status. Select metric
   names/tags from the inspected script; separate operation mixes whose latency
   budgets differ. Define error-rate and sample/completion criteria alongside
   percentiles.
4. Bound target load, runtime and generator resources. Configure early-abort
   thresholds only for the agreed stop condition, using `abortOnFail` and
   `delayAbortEval` where supported. Configure in-flight handling/graceful stop;
   forced interruption can skew latency and completion results.
5. Retain raw output or the configured metric export plus workload/config/version
   identity. Compare an equivalent baseline from the same generator location.
   Before attributing degradation, check generator saturation, dropped work,
   response errors and relevant target telemetry.

Official documentation: [thresholds](https://grafana.com/docs/k6/latest/using-k6/thresholds/),
[open and closed workloads](https://grafana.com/docs/k6/latest/using-k6/scenarios/concepts/open-vs-closed/),
[dropped iterations](https://grafana.com/docs/k6/latest/using-k6/scenarios/concepts/dropped-iterations/),
[graceful stop](https://grafana.com/docs/k6/latest/using-k6/scenarios/concepts/graceful-stop/) and
[API workload modeling](https://grafana.com/docs/k6/latest/testing-guides/api-load-testing/).
These explain adaptation; they do not authorize a different target or workload.
